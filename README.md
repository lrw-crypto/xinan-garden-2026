# 草商輔導寺
有心誠則靈，努力自有光。

Vite + TypeScript + three.js（r170，內含於 src/vendor）+ Firebase Authentication / Realtime Database。庭院是以程式建模的 3D 黏土風場景（青松、梅樹、錦鯉池與拱橋、青綠瓦屋頂、紅燈籠、繪馬架），全部由基本幾何體組成，沒有使用外部模型，也沒有複製參考圖或參考網站的素材。學生公仔為原創生成的透明立牌，胸口疊上原始校徽。匿名登入，不收集真實姓名、Email 或密碼。

## 本機開發
需要 Node.js 22+、Java 21（Firebase Emulator）。
```sh
npm ci --cache /tmp/npm-cache
npm run build
npm test
npx playwright install chromium
npm run test:browser
npm run dev
```
正式 Firebase 設定在 src/firebase.ts。資料庫鎖定時會明確顯示權限錯誤，不會以假人數冒充多人連線。
本機驗證可先執行：
```sh
npx firebase emulators:start --only auth,database --project demo-garden
VITE_EMULATORS=true npm run dev
```
Emulator 模式只連到本機 9099/9000，不寫入正式資料庫。禁止將 VITE_EMULATORS=true 用於正式建置。

## 雙人測試
1. 啟動 Emulator 與 Emulator 模式 Vite。
2. 用兩個獨立瀏覽器設定檔或一般與無痕視窗進入網站，各取不同暱稱。
3. 確認兩側皆顯示 2 位在線，互相點擊道路，觀察人物、暱稱、移動同步。
4. 一方進入靜心、祈福、長椅，另一方應看到狀態與固定表情。
5. 同時排隊，檢查順位、8 秒後輪替與祝福卡。
6. 寫私密願望，另一身分不得讀取；公開願望重新開啟面板可見。
7. 關閉其中一個視窗，等待 Firebase 偵測斷線，確認人數下降。中斷網路再恢復亦需測試。
8. 正式部署並套用規則後，用兩台不同手機重複以上步驟。正式站測試與 Emulator 測試須分別記錄。

`npm test` 會啟動 Auth / RTDB Emulator，測試安全規則及兩個獨立驗證身分透過真實 RTDB SDK 訂閱同步移動，不代表已驗證正式 Firebase 或真實手機。

## 發布安全規則（需您操作）
不會自動部署規則。先執行 npm test 通過後：
1. Firebase 控制台選擇 **xinan-garden-2026**。
2. Realtime Database → 新加坡資料庫 →「規則」。
3. 備份目前規則，貼入根目錄 database.rules.json 全部內容，按發布。
4. Authentication → Sign-in method 確認 Anonymous 啟用。
5. Authentication → Settings → Authorized domains 確認 lrw-crypto.github.io（開發需要時加入 localhost）。
6. 使用兩個瀏覽器驗證，並觀察資料庫用量。

規則預設拒絕根節點讀寫；驗證使用者可讀角色、公開願望、隊列；只有 UID 本人能寫角色與隊列、讀寫私密願望。欄位採白名單，限制暱稱、造型、色彩、座標、狀態、文字長度。公開文字有簡易不當用語過濾，**並非完整內容審核**；上線課堂需教師監督與處理不當內容。匿名使用者仍可建立多個身分；純前端不具反濫用、速率強制或完整管理機制。

## 補運隊列限制
以每 UID 的 transaction 建立伺服器時間戳，按時間與 UID 穩定排序，只能修改自己的紀錄，onDisconnect 清除。正常客戶端第一位停留 8 秒後離隊。規則拒絕回填過去時間或改寫他人紀錄；但無可信後端，無法保證惡意客戶端不提早宣稱完成、不佔住隊首、不建立多帳號，也無法伺服器強制完成輪替。勿宣稱不可插隊或具備完整公平性。人物移動每秒最多約 5 次更新。

## 開發環境
既有 checkout 位於 /workspace/xinan-garden-2026，每個雲端任務已隔離，不需額外 worktree。
npm ci --cache /tmp/npm-cache 可避開受限的家目錄快取路徑。

瀏覽器整合測試：執行 npm run test:browser，會自動啟動 Emulator 與 5174 埠測試伺服器。需要已安裝 Chromium（本機 /usr/bin/chromium 或 Playwright Chromium）。CI 上傳 browser-results 截圖供檢查。此為 Chromium 模擬手機寬度，尚不代表真實 iPhone Safari 驗證。

學生公仔已採藍白制服，短髮／長髮眼鏡造型；靜心與休息使用盤腿合十、閉眼姿勢。胸口直接使用使用者上傳的 public/art/school-emblem.png，僅等比例縮放，不重畫、不染色、不左右翻轉。

## 3D 庭院與操作
- 走路：點地面會自動繞過池塘、建築與樹走過去（池塘只能從拱橋通過）；桌機可用 WASD 或方向鍵，空白鍵跳躍，E 進入附近的互動點。
- 鏡頭：跟著自己的人物。拖曳可平移畫面（按「拖曳：平移／旋轉」切換成旋轉），雙指可縮放與旋轉，滾輪縮放，右鍵或 Shift 拖曳旋轉；「找自己」回到人物身上。
- 互動：點場景上的景點標籤會走過去並開啟；走到附近時上方會出現「進入○○」按鈕。右側（手機在下方）的五個按鈕仍可直接開啟。
- 人物走路：站姿圖沿褲腳分成上半身與左右腿三片，兩腿繞髖部交替擺動（橫向移動時前後擺腿，朝鏡頭或遠離鏡頭時交替抬腳），身體每一步輕輕起伏。步伐由實際走過的距離推動（每步 0.8 單位），所以腳不會在地上滑；停下時雙腿回到站姿。手臂不會擺動，這仍是立牌而不是 3D 人物模型。
- 校徽直接使用 school-emblem.png，疊在胸口，不重畫、不染色、不翻轉。
- 其他同學的位置每秒約更新 5 次，畫面上以滑行補間。跳躍只顯示在自己的畫面，不會同步。
- 走進或靠近靜心亭時，屋頂會變透明。鏡頭繞到圍牆外時，擋住視線的那面牆會收起。
- 祈福：送出後繪馬架上會多一塊粉色繪馬（只有自己看得到，重新整理後消失）。
- 補運：排隊同學依順位在小屋門口排成一列；輪到時站到門口，三顆星環繞，對話框依序顯示掃走煩惱、補充勇氣、星光環繞，結束後抽一張祝福卡。
- 休息長椅已移除。改為「點同學打氣」：點庭院裡任何一位同學，選「加油／謝謝／陪伴」，選單自動關閉，那兩個字會顯示在送出者自己頭上 5 秒，所有人都看得到。
- 公開心願每天清空：台灣時間凌晨 0 點以前寫的公開心願一律不顯示，並從資料庫刪除。網站沒有後端排程，刪除是由午夜後還開著或第一個打開網站的同學的瀏覽器代為執行（開著的頁面會在 0 點後約 5 秒自動清一次）；**需要先把新版 database.rules.json 發布到 Firebase**，規則才允許任何已登入者刪除「今天 0 點以前」的公開心願。發布之前舊心願仍留在資料庫，但畫面上已經不會顯示。私密心願不受影響。
- 走進靜心亭就會自動坐上蒲團並跳出時間選擇，不必再點「靜心亭子」；四個蒲團都有人時走不進去，畫面會跳出「現在蒲團滿位，請排隊稍等」。
- 心願文字把關（src/moderation.js）：送出前與顯示前都會檢查不雅用詞、負面或攻擊性字眼、告白用語，以及電話、信箱、網址、社群帳號、班級座號、地址、生日等個資；透露出想傷害自己的內容不會掛上樹，並顯示請找輔導老師與 1925 安心專線的訊息。**這是字詞與格式規則，不是 AI 模型**，換個說法或用諧音仍可能漏網，他人的姓名也無法辨識；公開心願仍需要老師留意。資料庫規則端只有最基本的過濾，改過的程式可以繞過前端檢查寫入，但其他人的畫面在顯示前會再檢查一次並隱藏不合格的內容。
- 靜心亭有四個蒲團，進入後直接以打坐姿勢坐下；選好時間後視窗自動關閉，倒數與呼吸提示顯示在庭院上方的小面板，可按「結束」。時間到或按「結束」後，人物會起身自己走出亭子，把蒲團讓出來。
- 庭院的樹是青松與梅樹交錯種植，取「輕鬆、沒事」的諧音；祈福樹是一棵開滿粉紅花的櫻花樹，取「櫻櫻沒帶事」的諧音。
- 錦鯉有紡錘形身體、會擺動的尾鰭、背鰭、胸鰭與花斑。
- 補運小屋已改為「補運光苗」：一株原創設計的大花苗，莖向補運台彎下，末端是發光的蓮花苞（沒有使用任何遊戲的造型或素材）。輪到時排隊視窗自動關閉，人物站上花苞下方的補運台，在畫面上滑兩下（或按「接引聖光」兩次）後聖光灑下、星星上升閃爍，結束後跳出祝福卡。25 秒內沒有滑動會自動開始，避免後面的同學久等。
- 版面為滿版：庭院佔滿視窗寬度與大部分高度。
- 資料庫座標仍是原本的範圍（x 55–945、y 150–535），在 3D 世界換算成 44 × 31 的地面。database.rules.json 相對最初發布的版本只改了一處：publicWishes 的寫入條件加上「可刪除今天 0 點（台灣時間）以前的公開心願」，需要重新發布。
- 人物造型仍為短髮、長髮兩種。新增造型需要新的透明人物圖，且要修改並重新發布 database.rules.json 的 style 白名單。
- package.json 仍列有 phaser，但程式已不再匯入，不會被打包；因開發環境無法更新 package-lock.json 而暫時保留。
- 若瀏覽器無法建立 WebGL，庭院不會顯示，但登入與五項互動的按鈕仍可使用。
